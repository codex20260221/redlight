# RedLight 0.6.0-rc.1 release validation

This is a release candidate for review and manual qualification, not a claim of completed hardware testing. The authorized scope for this preparation excludes launching RedLight, running MagRedProbe, or performing display/monitor tests. None of those actions were performed. Historical beta screenshots and changelog tests are not evidence for this candidate.

## Candidate scope

Preserve the native red-only filter, both established modes, Magnification-first selection, and legacy Strict Red gamma fallback. Add recoverable failure handling, usable tray/keyboard controls, remembered mode/brightness and optional activation-only fade-in, diagnostics, portable release delivery, and explicitly consented optional per-user startup and daily enable/restore scheduling. Startup remains unconfigured and scheduling remains Off by default; only explicit saved scheduling enables future automatic filtering. No translucent overlay or service is introduced.

## Magnification lifecycle correctness audit

The two backend objects have static storage duration in `main.cpp`; this audit preserves that ownership and the existing normal-close recovery guard. Backend preference edits only select the next start. Automatic startup fallback requires successful Magnification cleanup before initializing gamma. Failed startup capture has made no color write; no identity matrix is substituted for an unknown original.

| State | Invariant and allowed recovery |
| --- | --- |
| Released | No runtime ownership or readiness; initialize/capture before activation |
| Incomplete initialization or failed teardown | Runtime ownership retained, readiness false; cleanup must succeed before a fresh initialization/capture; no activation |
| Ready/off | Finite matrix capture completed; next activation captures the latest original |
| Confirmed red | Setter/read/comparison succeeded; original remains immutable until restoration |
| Unconfirmed activation/live rollback/restoration | Active confirmation false, original recovery retained; no recapture or new live writes; retry Restore/shutdown |
| Original restored, cleanup incomplete | No owned display restore remains; runtime cleanup can retry without another color write |

Confirmed fixes: API ownership no longer makes incomplete initialization report success; failed teardown invalidates readiness; successful owned writes require read-back; failed restoration drops active confirmation before the attempt; matrix comparison explicitly separates red-only exact-zero safety from finite arbitrary-original tolerance; every backend Magnification API call clears last-error before invocation and captures supplied codes before logging. Setter failure is never accepted merely because later output happens to match. Successful rollback restores prior confirmed red state/choices; unconfirmed rollback retains the original snapshot and resources. Diagnostic clearing, explicit inspection, and repeated ready/active initialization do not erase that obligation or replace the original with external output.

Ownership/termination findings: normal `WM_CLOSE` still refuses destruction after failed restoration. Incomplete shutdown now preserves live controls after a native queue error as well as ordinary quit, including an outer busy scope. Missing/destroyed controls retain the existing best-effort failure exit; the destructor retries and diagnoses failure but cannot outlive object/process destruction. Session-end query honors Windows intent. Both session-end restoration calls suppress direct failure UI and tray-refresh recursion; canceled end-session does not destroy controls, and committed failed restoration retains controls while Windows permits. [Windows may terminate after committed end-session](https://learn.microsoft.com/en-us/windows/win32/shutdown/wm-endsession); forced termination may bypass destructors. No shutdown veto, new owner architecture, or recovery guarantee after process death is introduced. Separate standalone identity reset now excludes stale errors and reports failed cleanup; it owns no prior-matrix snapshot.

External-tool limitations: [MagSetFullscreenColorEffect uses the most recent transform](https://learn.microsoft.com/en-us/windows/win32/api/magnification/nf-magnification-magsetfullscreencoloreffect). Another process can change output between setter/read, immediately after confirmation, or during restoration. Matching software read-back is neither atomic ownership nor physical-panel measurement. Restoration deliberately overwrites the current matrix with the captured original; it cannot merge another tool's intervening edits. Original restoration accepts finite coefficient differences within `0.000001f`, including expected zeros; red-only verification requires exact requested zeros. The original is never replaced during pending recovery.

They cover failed/invalid capture plus failed cleanup and repeated initialization/fallback, successful cleanup/fresh capture, cleanup-only readiness, activation/live failure matrices, partial/ignored setters, read failures/mismatches, failed/mismatched rollback, original-restoration retries, policy distinction, allocation-free confirmation/no-op reads, all native failure stages with absent/supplied errors, external-tool snapshot preservation, and queue-error/busy retention with later successful recovery.
