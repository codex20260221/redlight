## Verification boundaries

Brightness, optional startup, activation-only fade-in, and daily scheduling are implemented locally. Per-monitor work remains research/prototype only; native/hardware qualification is pending for all display features. Work is limited to local commits, with no pushes, PRs, issue edits, releases, GitHub Actions, or execution/testing of RedLight itself. Static analysis, builds, isolated fake-API code tests, and static package inspection are the permitted verification scope. Manual/native qualification is listed in [release validation](release-validation.md); current development stop/resume instructions are kept in the root development handoff.
