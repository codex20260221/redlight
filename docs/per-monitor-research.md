# Per-monitor research (issue #23)

Per-monitor filtering is **not implemented or qualified**. This research follows the [issue](https://github.com/michaelmawhinney/redlight/issues/23), the [planetarium/projector use case](https://github.com/michaelmawhinney/redlight/issues/23#issuecomment-5310658055), and the [proposed control-based probe](https://github.com/michaelmawhinney/redlight/issues/23#issuecomment-5518042811). No RedLight, MagRedProbe, native display experiment, or hardware test was run. Production backend selection, restoration ownership, manifest, and output remain unchanged.

## What the APIs establish

The current fullscreen transform affects the desktop; a windowed magnifier instead renders a captured source area into a host window. This is a possible **opaque transformed copy**, not a translucent red tint and not a proven per-output color pipeline. Microsoft's [Magnification overview](https://learn.microsoft.com/en-us/windows/win32/winauto/magapi/magapi-intro) describes layered hosts, full opacity, transparent mouse handling, 1:1 magnification, cursor options, and the WOW64 limitation. It does not qualify this arrangement for RedLight's projector isolation requirement.

| Area | Documented mechanism and remaining work |
| --- | --- |
| Per-control color | [MagSetColorEffect](https://learn.microsoft.com/en-us/windows/win32/api/magnification/nf-magnification-magsetcoloreffect) / [MagGetColorEffect](https://learn.microsoft.com/en-us/windows/win32/api/magnification/nf-magnification-maggetcoloreffect) set/read a control's matrix and require WDDM. Check both calls and red-only comparison before showing a host. This read-back still does not measure physical output. |
| Source | [MagSetWindowSource](https://learn.microsoft.com/en-us/windows/win32/api/magnification/nf-magnification-magsetwindowsource) uses desktop coordinates. A proposed 1:1 source rectangle must exactly match the destination monitor rectangle, including negative origins, and be revalidated after topology changes. |
| Capture recursion | [MagSetWindowFilterList](https://learn.microsoft.com/en-us/windows/win32/api/magnification/nf-magnification-magsetwindowfilterlist) supports exclusion; inclusion is unsupported on Windows 7+. A control excludes itself automatically. A multi-host probe should explicitly exclude every probe host from every control and verify the list; do not assume one control's self-exclusion prevents cross-control capture. |
| Input | [MagSetInputTransform](https://learn.microsoft.com/en-us/windows/win32/api/magnification/nf-magnification-magsetinputtransform) requires UIAccess, and its documentation includes mouse routing from Windows 10 version 1703. This needs reconciliation with the overview's transparent-host advice, especially for identical 1:1 rectangles. Do not claim click/touch/pen/keyboard passthrough from window styles alone. |
| DPI | [Process DPI awareness](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process) changes coordinate behavior and must be selected before HWND creation. A future separate x64 probe should declare its own reviewed PerMonitorV2 manifest; the current app has no DPI-awareness declaration and remains `asInvoker`, `uiAccess=false`. Do not change the application's privilege or DPI model as a research shortcut. |

Cursor behavior is independently unresolved. The [overview](https://learn.microsoft.com/en-us/windows/win32/winauto/magapi/magapi-intro) distinguishes the ordinary cursor from a control's magnified cursor. The first probe must leave global cursor visibility and input transformation untouched, then measure any colored cursor leakage/duplication. If strict red-only cursor behavior requires global changes, review their ownership/restoration separately before extending scope.

## Geometry and selection preconditions

Use full monitor bounds, not work-area bounds: taskbars must not become uncovered color strips. [MONITORINFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-monitorinfo) expresses monitor rectangles in virtual-screen coordinates, which may be negative. An independent native adapter must confirm a consistent pixel coordinate space; a rectangle supplied to a pure planner cannot prove DPI correctness.

Treat all-monitor filtering as the existing fullscreen path. A subset experiment must require a checked, current topology snapshot with unique transient region keys and separate display sources, exact source/destination rectangles, positive representable window dimensions, no overlapping regions, and no RedLight fullscreen/gamma restoration ownership. No monitor enumeration or mapping is added to production in this research.

Windows distinguishes [clone and extended topologies](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ne-wingdi-displayconfig_topology_id). **Inference:** a captured desktop region cannot independently recolor two physical targets that clone the same source image. Reject shared-source/clone/unknown topology for a subset experiment. Nonoverlapping rectangles alone are not proof of independent physical outputs; the native adapter must also establish source/target relationships. Do not persist enumeration order or raw HMONITOR values as monitor identities. Review durable device/path identity and unplug/replacement consent before any user-facing selection preference.

The code-only `tests/Prototypes/MonitorPlan.h` preflights supplied geometry into caller-owned storage. It describes one exact source/destination pair per selected region and bind it to a topology revision. It rejects invalid/ambiguous input and insufficient capacity before publishing any partial plan. Eight isolated scenarios cover its bounds, gates, publication, and allocation/native-call isolation; the full suite has 464 scenarios. It does not enumerate monitors, create windows, initialize Magnification, set colors/gamma/cursor/input, or establish that a plan can be displayed correctly.

## Future native probe boundaries

Keep a native probe separate from RedLight, disabled in the default build and excluded from the portable package. Build/static/fake checks are allowed; running it requires later explicit authorization for display/hardware validation. A successful build or fake API must never be called monitor-isolation validation.

1. Start only with explicit selected output and bounded duration after operator review of live topology. Refuse unknown/clone geometry, an existing RedLight owner, or unsafe privilege/DPI prerequisites. Never reset another tool's fullscreen matrix or gamma ramp to obtain eligibility.
2. Create hosts hidden. Configure checked opacity, 1:1 transform, source, exclusions, and strict red-only color/read-back before any becomes visible. Initially use one selected monitor; add multiple controls only after independent exclusion/input/cleanup review. Do not show a white/unfiltered intermediate host.
3. Keep manual close/recovery and a checked bounded timer. On Escape/close/failure/topology/DPI/suspend/session change, hide/destroy owned hosts immediately; do not retarget them to a replacement monitor. Check removal/destruction/runtime cleanup, retaining handles and controls after recoverable failures. A hidden host is not proof its native resources were released.
4. Do not touch global fullscreen/gamma/cursor/input state in the first probe. Local control teardown should remove only the experimental copy. If runtime initialization/teardown is ambiguous, track ownership separately from completed readiness as in the existing Magnification audit. Never add runtime backend switching to production on the strength of this experiment.
5. External display tools may transform the source, destination, or unselected outputs independently. Do not adopt their matrix as a new RedLight original or promise untouched physical projector output based solely on per-control read-back.

## Evidence required before production consideration

Code-only preflight tests: negative origins, portrait/rotated rectangles, gaps/edge-touching layouts, full bounds, single/multiple selected regions, all/none selection, malformed/duplicate/overlapping/shared-source input, arithmetic limits, stale revision, retained global recovery gate, bounded publication, and allocation/native-call isolation. These tests establish only planning properties.

Later fake-native tests: every create/configure/set/get/show/hide/destroy/timer/runtime failure, partial application and cleanup ownership, all-host exclusion lists, zero green/blue/black offsets across Strict/Luma/brightness, immediate teardown on cancellation/topology/session change, and no global writes. The existing MagRedProbe only exercises fullscreen effects; it provides no evidence for windowed controls.

Manual Windows work remains pending: prove the projector is unchanged while a selected monitor is strictly red-only, check black/white/primaries and cursor, cross-monitor windows and menus, mouse/keyboard/touch/pen and secure/elevated windows, mixed DPI/rotation/negative origins, taskbars/fullscreen/video/acceleration/HDR, source/exclusion feedback, frame latency/performance, hotplug/sleep/lock/session/Explorer recovery, forced termination, and original global state after every cleanup path. Until those results exist, do not expose a production per-monitor selector or claim the feature works.
